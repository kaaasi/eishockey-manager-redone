## 2. Befunde

**RR-01 (P2) – DEB-Pokal, schneller Weg: Zusatzwurf auch für ungleiche Paarungen vor der letzten offenen Paarung des Termins.**
[`MatchEngine.Minutes.cs:700`](https://github.com/kaaasi/eishockey-manager-redone/blob/d6d556071cd807eeaf3242bf14df7f84937bd641/src/EishockeyManager.Core/MatchEngine.Minutes.cs#L700)
gibt bei `h != g` ohne Wurf zurück. Original (`ndisasm -b16 -o <a> -e <a> em.exe`, `disasm.py` für 0x32AA3/0x3731F):
- 0x3731F rechnet die Paarungen der Zeile 0 in Platzfolge (0x377A3–0x377B3, Schritt 2) und ruft **je Paarung** nach dem Eintragen
  0x32AA3 (0x376E1); jede Rückgabe ≠ 0 führt zum Wurf (0x376E9 `or al,al; jnz 0x376F0`).
- Noch nicht gerechnete Paarungen stehen auf 0:0: 0x34C94–0x34CAA setzt nach jedem gewerteten Spiel 5C4B/5C4C := 0, 0x34F7D
  (0x34FA3, 0x34FBA) zu Rundenbeginn D014 und 5C4B := 0. Ihr D014-Byte ist 0 (≤ 0x63, 0x32B71/0x32B88) → offen.
- 0x32AA3, Zeile 0 (0x32AF4): markiert bei Heim = Gast (0x32B23) **oder Heim − 30 = Gast** (0x32B3F–0x32B5A) → +30 (0x32BAA) und
  meldet 1 (0x32B92, 0x32E1C). Eine offene spätere Paarung wird also bei jedem Aufruf wieder erkannt (0:0 → 30:0 → 60:0 …, beim
  eigenen Rechnen überschrieben, 0x376B2–0x376C5). Der Play-off-Zweig prüft nur Gleichheit (0x32CCC) – daher dort nur die erste
  Paarung (`FirstPlayoffPairingOfDate`, „danach kein Gleichstand mehr“); im DEB-Pokal alle außer der letzten offenen.
- Folge für eine ungleiche Paarung: 0x37724–0x37748 würfelt bis Heim + x ≠ Gast + y (Heimbyte ohne Marke), 0x3775D–0x37774
  Heim + x + 30, 0x37788 Gast + y; 0x34C06–0x34C2A zieht die Marke ab, 0x34C76 wertet die Summe (Heim ≥ Gast → Platz 2k). Der
  Sieger kann kippen (Abstand 1: x = 0, y = 2 → 1/7); Anzeige ein Punkt, D014-Byte + 30, je Paarung mindestens zwei Züge mehr im
  Zufallsstrom. Bei der letzten offenen Paarung (und im Endspiel, FILE44) stimmt der PR.
- Spielstände unterscheiden das nicht: Alle DEB-Termine mit mehreren Paarungen in FILE01–FILE76 (FILE24/25 Runde 1, FILE39–43
  Runde 3) sind Managertage (Köln, Verein 2, in 5CFB Zeile 0) → Minutenweg; FILE44 hat nur eine Paarung. Beleg ist daher die
  Lesung oben; ein Videobild eines DEB-Ergebnisbildschirms ohne Managerverein mit mehreren Punkten würde ihn bestätigen.
- Probe Remake (temporärer Test in Kopie, nicht committet): `FastCupResultWithTie(…, knockOut: true, debCup: true)` für alle
  ungleichen Ergebnisse von Saat 0 … 1999 muss würfeln → **rot, Expected 1728, Actual 0**
  (`dotnet test tests/EishockeyManager.Core.Tests --filter FullyQualifiedName~ZzReviewProbe`).
- Fix: in `MatchEngine.Live.cs` ein `debExtraRoll` wie `playoffExtraRoll` (noch eine offene, an diesem Termin nicht gerechnete
  Paarung hinter dieser in `CupsDeb.PlayDay`); in `FastCupResultWithTie` bei `debCup && debExtraRoll && h != g` bis ungleich
  würfeln, eine Marke; `CupMatch.FromReport` muss dann im DEB-Pokal auch ungleiche Ergebnisse mit Zusatztoren und Marke 1 tragen.
  Regressionstest mit zwei Paarungen an einem Termin.
